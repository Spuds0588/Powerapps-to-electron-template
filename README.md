# Power App to Electron Template

[Try the Configuration Wizard Here](https://spuds0588.github.io/Powerapps-to-electron-template/)

## 1. Overview

This repository provides a production-ready template for packaging a Microsoft Power App into a
standalone **desktop application** built with Electron. It acts as a powerful bridge, allowing you
to create a seamless enhancement layer over existing web applications.

The app runs in a dual-pane desktop window: your Power App lives in a **persistent sidebar**, while
the main pane is a fully navigable embedded browser. The main process extracts context from the main
pane — the active URL, specific DOM element values, and local storage keys — and passes it into the
Power App as URL parameters. Your Power App can then react to whatever the user is looking at, with
no tab-switching required.

The wizard is built with vanilla HTML, CSS, and JavaScript, ensuring it is lightweight, has no
backend, and deploys to GitHub Pages for free.

**Project ID:** `spuds0588-powerapp-electron-template-v1.0.0`

> Sister project: [`Powerapp-to-Extension-Template`](https://github.com/Spuds0588/Powerapp-to-Extension-Template)
> — the same concept packaged as a Chrome/Edge side-panel extension.

## 2. Key Features

*   **Dual-Pane Desktop Shell** — A native window with the Power App in a fixed-width sidebar and an
    embedded browser in the main pane, using modern `WebContentsView` (not the deprecated
    `BrowserView`).
*   **Visual Configuration Wizard** — A web UI on GitHub Pages that writes `config.json` directly
    into your project folder using the File System Access API. No manual code editing or unzipping.
*   **Context Passing** — Send critical data to your Power App:
    *   **`tabURL`**: The full URL of the main pane.
    *   **`tabBody`**: A JSON object of values from specific HTML elements (by `id`).
    *   **`tabLocalStorage`**: A JSON object of specified local storage keys.
*   **Flexible Triggers** — Update the Power App on page navigation, on a recurring timer, or both.
*   **State Preservation** — The sidebar is only reloaded when the generated URL actually changes, so
    a heavy Canvas app never loses the user's work mid-task.
*   **Microsoft Entra ID (Azure AD) Support** — Native handling of authentication pop-ups so Power
    Apps can log users in without breaking the dual-pane layout.
*   **Zero IPC / Preload** — Context is captured with `webContents.executeJavaScript` from the main
    process only. No `preload.js`, no message-passing plumbing.
*   **Cross-Platform Packaging** — Electron Forge makers for Windows (Squirrel) and macOS/Linux (ZIP).

## 3. How It Works

The app is composed of two files that work together:

1.  **`config.json` (The Control Center)** — Generated by the wizard. Defines your Power App URL,
    layout sizing, which data to capture, and which events trigger an update.
2.  **`main.js` (The Engine)** — Reads the config, creates a `BaseWindow` with two
    `WebContentsView` instances, and maintains their layout on resize. It listens for navigation and
    timer triggers, scrapes the main pane, builds a new Power App URL, and loads it into the sidebar
    **only if it changed**.

The decoupled design keeps the app efficient: scraping only runs when a configured trigger fires.

## 4. Getting Started: 5-Minute Quick Start

### Step 1: Download the Template
Clone or download the repository into a folder on your computer:

```bash
git clone https://github.com/Spuds0588/Powerapps-to-electron-template.git
cd Powerapps-to-electron-template
```

### Step 2: Configure with the Wizard
Open the **[Configuration Wizard](https://spuds0588.github.io/Powerapps-to-electron-template/)**,
fill in your Power App URL and triggers, then click **Save config.json to my folder** and select your
project folder. Prefer no browser permissions? Click **Download config.json** and drop the file into
the project folder yourself.

> Just want to test fast? Copy `config.example.json` to `config.json` and edit the `powerAppUrl`.

### Step 3: Install and Run

```bash
npm install
npm start
```

The window opens with your Power App on the left and the main browser pane on the right.

### Step 4: Test It!
By default the app already passes the main pane's URL to your Power App as `tabURL`. Navigate around
the main pane and watch your Power App react (once you add the Power Fx from section 6).

## 5. Detailed Configuration (`config.json`)

The wizard produces this file, but you can also edit it by hand. Missing or partial files safely
fall back to defaults.

```json
{
  "powerAppUrl": "https://apps.powerapps.com/play/e/your-environment-id/a/your-app-id?tenantId=your-tenant-id",
  "defaultMainUrl": "https://www.bing.com",
  "sidebarWidth": 420,
  "windowWidth": 1440,
  "windowHeight": 900,
  "parameters": {
    "includeTabUrl": true,
    "includeTabBody": false,
    "targetIds": ["usernameField"],
    "includeLocalStorage": false,
    "targetLocalStorageKeys": ["sessionToken"]
  },
  "triggers": {
    "onUrlChange": true,
    "onTimer": {
      "enabled": false,
      "interval": 2000
    }
  }
}
```

### Top-level keys
| Key | Default | Description |
| --- | --- | --- |
| `powerAppUrl` | placeholder | **Required.** The base URL of your Power App. Existing query params are preserved. |
| `defaultMainUrl` | `https://www.bing.com` | The page the main pane opens to at launch. |
| `sidebarWidth` | `420` | Width of the Power App sidebar, in pixels. |
| `windowWidth` / `windowHeight` | `1440` / `900` | Initial window size (clamped to your screen). |

### `parameters`
Control which data is sent to your Power App. Keeping this tight avoids overly long URLs.
*   `includeTabUrl` — passes the main pane URL as `tabURL`.
*   `includeTabBody` + `targetIds` — scrapes the listed element IDs into a JSON object as `tabBody`.
*   `includeLocalStorage` + `targetLocalStorageKeys` — reads the listed keys into `tabLocalStorage`.

### `triggers`
*   `onUrlChange` — update when the main pane navigates (great for single-page apps).
*   `onTimer.enabled` / `onTimer.interval` — update on a recurring interval (ms). Use with care.

## 6. Preparing Your Power App to Receive Data

Your Power App reads the incoming parameters with the Power Fx `Param()` function. Place this in the
**`OnStart`** property of the App, or the **`OnVisible`** property of the relevant screen:

```powerapps-dot
// 1. Capture the raw URL parameters
Set(gblRawTabURL, Param("tabURL"));
Set(gblRawTabBody, Param("tabBody"));
Set(gblRawLocalStorage, Param("tabLocalStorage"));

// 2. Process the parameters
If(!IsBlank(gblRawTabURL),
    UpdateContext({ varTabURL: gblRawTabURL })
);

// tabBody and tabLocalStorage arrive as JSON strings and must be parsed
If(!IsBlank(gblRawTabBody),
    Set(gblTabBodyObject, ParseJSON(gblRawTabBody))
);

If(!IsBlank(gblRawLocalStorage),
    Set(gblLocalStorageObject, ParseJSON(gblRawLocalStorage))
);
```

**Accessing parsed data:**

```powerapps-dot
// In a Label's Text property:
Text(gblTabBodyObject.usernameField)

// Nested values work too:
Text(gblLocalStorageObject.userPreferences.theme)
```

## 7. Packaging & Distribution

When you are happy with your app locally, generate a distributable with Electron Forge:

```bash
npm run make
```

Outputs land in the `out/make/` folder:
*   **Windows** — a Squirrel `.exe` installer.
*   **macOS / Linux** — a `.zip` app bundle.

Because `config.json` is user-specific, it is **not** bundled into the app. Before distributing,
ship a `config.json` (or the wizard) alongside the installer, or pre-configure it for your users.

For internal IT deployment, you can sign the Squirrel installer and push it through your usual
software-distribution tooling (e.g. Microsoft Intune).

## 8. Testing and Debugging

*   **Main pane** — press `Ctrl/Cmd + Shift + I` while it is focused to open its DevTools.
*   **Power App sidebar** — click into the sidebar and press `Ctrl/Cmd + Shift + I`.
*   **Reload** — press `Ctrl/Cmd + R` to reload the focused pane.
*   **Console logs** — the main process logs with the `[PowerApp Desktop]` prefix so you can trace
    configuration loading, popups, and every sidebar update.

Common issues:
*   **"Blank screen when logging in"** — verify popup handling in `setWindowOpenHandler`.
*   **"Wizard cannot save file"** — the wizard needs a Secure Context (HTTPS/GitHub Pages) and a
    Chromium-based browser. Use the download fallback if `showDirectoryPicker` is unavailable.
*   **"The Power App keeps refreshing"** — confirm the identical-URL guard is working in
    `updatePowerApp()`; check for a timer that fires faster than your data changes.
*   **"Nothing is scraped"** — ensure `includeTabBody` is on, `targetIds` are correct, and the page
    is not inside a cross-origin `iframe` (standard CORS policies apply).
